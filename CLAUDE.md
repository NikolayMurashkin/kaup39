# CLAUDE.md — kaup39 (демо-версия сайта «Кауп»)

Репозиторий демо для владельцев kaup39.ru. Решения по студии — `../PLAN.md`,
порядок работ и критерии приемки — `../ROADMAP.md` (фаза 6), артборд направления —
`../design/kaup/Kaup.dc.html`.

## Контент владельцев

Владельцы «Каупа» письменно разрешили использовать свой контент (23.09.2026, решение записано в `../PLAN.md`):
тексты и фотографии могут лежать в git и попадать в тесты, код может называть площадки, таверны и услуги
своими именами, репозиторий можно открыть публично. Рабочая копия контента — в CMS; файл, из которого
она импортирована, и выгрузка исходного сайта лежат в `../research/kaup39/`. Выдуманные отзывы и стоковые
люди с исходной `/corp` не переносятся и с разрешением: оно касается настоящего контента, а не поддельного
(это сторожит проверка импорта).

Касса одна — Radario. Ссылок на `edinoepole.ru` в коде и данных быть не должно.

## Стек

Next.js 16 (App Router, Turbopack), React 19, TypeScript, SCSS-модули, Payload 3 на Postgres. Один язык —
русский, маршрутизации по локалям нет. Пакетный менеджер — Yarn 4 через corepack, Node 24. Пакет — ESM
(`"type": "module"`, как в шаблоне Payload: иначе CLI Payload грузит конфиг как CommonJS и не находит
модули без расширений), поэтому JSON импортируется с `with { type: 'json' }`.

## Две темы

Тема хранится в куке `theme` (`dark` | `light`), читается на сервере в `src/lib/theme.ts`
и рендерится в `data-theme` на `<html>`. Темная — основная, она же значение по умолчанию:
пустая кука и мусор в ней дают темную (`resolveTheme`, тесты в `tests/unit/theme.test.ts`
и `tests/e2e/shell.spec.ts`).
Переключатель — `ThemeToggle` в шапке: пишет куку, сразу меняет `data-theme` и просит сервер
перерисовать страницу (`router.refresh()`), потому что у темы свой кадр первого экрана — вечерний
у темной, дневной у светлой, и выбирает его сервер.

## Токены направления

`src/styles/tokens.scss` — перенос таблицы токенов артборда один в один:

- `:root` — темная тема (шрифты, размеры, цвета, срезы, тени, зернистость, вуали);
- `[data-theme='light']` — что меняется в светлой;
- `@media (max-width: 640px)` — узкая ширина артборда (390): размеры и вертикальный скрим.

Артборд лежит в плановой части студии и намеренно не входит ни в один git, поэтому на CI
его нет. Тесты сверяют SCSS со снимком `tests/fixtures/artboard-tokens.json`, а на маке тот же
тест пересобирает снимок из артборда и падает при расхождении. Правишь артборд — гони
`yarn sync:tokens` и коммить обновленный снимок.

Значения сравниваются после нормализации записи (Prettier переносит длинные градиенты и срезает
хвостовой ноль), то есть тест ловит подмену значения, а не форматирование. Нормализация считает
числа числами, а остальное оставляет как есть: точка в `url(grain2.png)` должна дожить до
сравнения, иначе она сравнялась бы с `url(grain2png)`.

Кадры первого экрана (`--photo-night`, `--photo-day`) в токены не переносятся и выброшены самим
генератором снимка: в артборде это пути к выгрузке вне репозитория, а на страницах кадр приезжает из CMS.

## CMS

Payload 3 живет в том же приложении: админка `/admin`, REST `/api/*`, GraphQL выключен. Интерфейс
админки по-русски. Локально база — Postgres 15 из `docker-compose.yml` на `127.0.0.1:5433` (порт не
5432, чтобы не спорить с базами других проектов), две базы: `kaup39` для разработки и `kaup39_test`
для интеграционных тестов. Схему Payload накатывает сам в режиме разработки; миграции для сервера
заводятся вместе со стендом. Переменные — `DATABASE_URL` и `PAYLOAD_SECRET` в `.env`, образец — `.env.example`.
`MEDIA_DIR` — каталог медиатеки от корня репозитория, по умолчанию `media`; меняют его только e2e-сервер
и Lighthouse на CI. `E2E_DATABASE_URL` — адрес e2e-базы для Playwright, по умолчанию `kaup39_e2e` в том же
контейнере; на CI его задает сервис Postgres. Playwright `.env` не читает: переменная задается только
окружением при запуске, в `.env` она молча не подействует.
Сборке база не нужна: админка и REST рендерятся на запрос, поэтому CI собирает приложение без `.env`.

**Коллекции** (`src/cms/collections/`): `events` (название, slug, описание, «входит»/«за доплату»,
галерея, цены по видам билета, ссылка на кассу, даты через join), `schedule` (событие, день, начало,
конец, огненное шоу), `pages` (главная, «как доехать», корпоративы: заголовок, подзаголовок, кадры
первого экрана и разделы из блоков `text`/`list`/`prices`/`links`/`photos` с якорями), `zones` (со знаком
площадки из спрайта направления),
`taverns` (с меню по разделам), `media`, `users`. Контакты, соцсети, точка поселения на карте и инструкция
по возврату билетов — глобал `site`: они нужны на каждой странице. Точка на карте необязательна: колонки
NOT NULL в базе с уже заполненным глобалом Payload без вопроса не добавит (`yarn import:content` зависал
на подтверждении), а без точки страница просто не показывает кнопку карты.

**Касса одна — Radario.** Ссылка на билет — единственное поле-ссылка у события, обязательное,
с валидатором `validateTicketUrl`: адрес разбирается целиком, поэтому не проходят `edinoepole.ru`,
`https://https://radario.ru/…` и `radario.ru.example.com`. Из админки такая ссылка не сохраняется
(проверено руками и `tests/integration/cms.test.ts`), `tests/unit/ticket-links.test.ts` сторожит,
что валидатор висит на поле и второго поля-ссылки у события нет. Кнопку «Купить билет» можно поставить
и в раздел страницы, поэтому все остальные поля-ссылки (`links`, пункты `list`, соцсети в `site`) идут
через `validateLinkUrl`: полный адрес с https, и имя второй кассы не встречается ни в адресе, ни
в разобранном хосте (так не проходят точка в конце хоста, `%2E` и двойная схема). Тест обходит все
коллекции и глобалы из `src/cms/schema.ts` — того же списка, что берет конфиг, поэтому новое поле-ссылка
без валидатора в любой из них его роняет.

**Даты.** День хранится полднем UTC — так его сохраняет календарь админки (`pickerAppearance: 'dayOnly'`),
так же пишет импорт. Страницы получают день строкой `YYYY-MM-DD` по Калининграду из `getSchedule`
(`src/cms/schedule.ts`), время — строками `ЧЧ:ММ`, конец позже начала проверяется валидатором
(«с 12:00 до 12:00» с исходной `/tur` не пройдет). Кеша у `getSchedule` нет: страницы и так
рендерятся на каждый запрос (layout читает куку темы), и правка в админке видна со следующей загрузки —
это сторожит интеграционный тест. Добавишь кеш — добавь и сброс по `afterChange`.

**Факты и тексты разведены.** В git — только `src/cms/facts.ts`: slug событий, ссылки Radario, цены
и 41 дата видимой таблицы `/tur` (с двумя правками октября по `/denvikingi`, решение Николая 23.09.2026).
`tests/unit/schedule-facts.test.ts` держит таблицу `/tur` дословно и сравнивает с ней сиды, а на маке
еще и разбирает сам `../research/kaup39/html/tur.html` по координатам элементов Тильды: видимыми
считаются только элементы внутри артборда. Список «27 сентября… + Самайн 01.11» на `/tur` вынесен
Тильдой за артборд, посетителю не виден и в сиды не входит.

Тексты, названия и подписи фотографий — в `../research/kaup39/content/content.json`, вне git.
`yarn import:content` (`scripts/import-content.ts`, запускается через `payload run`) сначала проверяет
файл (`scripts/content-check.mts`): знак вне `GLYPHS` сабсета шрифтов, «ё», вернувшиеся опечатки
исходника, `edinoepole`, выдуманные отзывы и служебный мусор `/corp`, фотография не из выгрузки
владельцев или со стоковой `/corp`, расхождение событий с `facts.ts` — любое из этого останавливает
импорт до записи в базу. Потом он загружает фотографии в медиатеку и обновляет записи по естественным
ключам (slug, имя файла, событие + день + начало): повторный запуск не плодит дублей, но перезаписывает
то, что поправили в админке. Удалять импорт ничего не умеет: поменяешь в `facts.ts` день или начало
у даты — старая строка останется в базе рядом с новой, ее надо снять в админке. Перед переносом базы
на стенд это стоит помнить. Правила проверки сторожит `tests/unit/content-check.test.ts` на
придуманных образцах, чтобы тест шел и на CI.

Покрытие знаков контента CMS проверяется только импортом: тест `font-subset` видит тексты репозитория,
а не базы. Знак, набранный в админке руками, не поймает ни импорт, ни этот тест: проверка нужна там,
где тексты CMS впервые отрисуются на странице.

## Главная

`src/app/(site)/page.tsx` читает все одним заходом `getHome()` (`src/cms/home.ts`, склеен `cache`
на запрос) и собирает страницу сверху вниз: шапка, первый экран с панелью ближайшего события, лента
ближайших дат, разделы страницы из CMS по порядку, железные плашки «как доехать» и трансфер, подвал.

**Ближайшие даты** — `upcoming()` (`src/cms/upcoming.ts`): дата остается, пока событие не закончилось,
время сравнивается по Калининграду. Нет ни одной будущей даты — нет ни панели, ни ленты, ни раздела
с якорем `events`: пустых блоков на главной не бывает. Ссылка на расписание при этом остается
в первом экране — кнопка под подзаголовком, а не только в панели: на 390 панель уходит ниже первого
экрана.

**Якоря — договор между CMS и версткой** (`HOME_ANCHORS`, `DIRECTIONS_ANCHORS` в `src/cms/consts.ts`).
К разделу `zones` пристраиваются плитки площадок, к `kitchen` — таверны, раздел `events` уходит в ленту
дат, `camping` — цель пункта «Кемпинг» в меню, плашка трансфера собирается из разделов `transfer`
и `transfer-price` страницы «как доехать». Переименуешь якорь в админке — плитки и таверны не пропадут,
а встанут в конец страницы; ссылка из меню на `/#camping` сломается, это ловит e2e-тест якорей.

**Разделы CMS** рисует `CmsSections`: текст или галерея открывают раздел, а цены, списки и ссылки
пристегиваются к открытому (`group.ts`, юнит-тест) — так «кемпинг», его цены и услуги стоят под одним
заголовком. Тексты из CMS проходят типограф (`typograph` в `src/lib/format.ts`): неразрывный пробел
после коротких слов ставится при отрисовке, в базе его нет.

**Адреса страниц** (`src/lib/consts.ts`): `/raspisanie`, `/sobytiya/<slug>`, `/kak-doehat`,
`/korporativy`. Расписание и «как доехать» уже есть; пока блоки остальных не сделаны, ссылки на них ведут
в 404 — адреса правильные, страниц еще нет.

**Раскладка держит один брейкпоинт, 640** (так требует `design-tokens.test.ts`): между 641 и 1440 шапка
переносит меню на свою строку, панель первого экрана уходит под текст, сетки площадок и галереи
раскладываются через `auto-fill`/`auto-fit`. Промежуточный медиазапрос тест не пропустит.

**Кадр первого экрана** идет с `preload` и качеством `HERO_QUALITY` (40, `src/lib/images.ts`): под скримом
плотностью 0,7–0,97 артефакты не видны, а на мобильной ширине кадр и есть LCP — при качестве 75
он весил 330 КБ, и один прогон Lighthouse из трех падал до 86. Оптимизатор отдает AVIF и WebP и только
файлы медиатеки (`images.localPatterns`).

### Расхождения главной с артбордом

- **Заголовок первого экрана** — название из CMS капителью (это и есть текст `h1`), а под ним те же слова
  рунами, каждое слово своей надписью, чтобы строка переносилась по словам. На артборде был свой
  заголовок «Живой день в эпохе викингов» только рунами и строка про Балтийский путь: тексты первого
  экрана теперь приходят от владельцев. Последнее слово рун — акцентное, как вторая строка на артборде.
- **Кнопка «Расписание и цены» под подзаголовком** — на артборде ее нет, ссылка была только в панели.
- **Верхняя строка** — только адрес: руны футарка из Unicode не рисуются (шрифта рун нет, руны — отрезки),
  а подпись «старший футарк» к нашему алфавиту была бы неправдой.
- **Меню** — «Расписание и цены», «Как доехать», «Корпоративы», «Кемпинг»: отдельной страницы «События»
  в пяти страницах демо нет. «Билеты» в шапке ведут в расписание, а не в кассу: у каждой даты своя
  кнопка кассы. Добавлены переключатель темы и бургер на `<details>` для узкой ширины.
- **Заголовки разделов** набраны Ponomar, а не рунами: они приходят из CMS длинными («„Кауп“ —
  реконструкция средневекового городища»), рунами их не прочитать.
- **Разделов больше, чем на артборде**: «о поселении», таверны с меню (свернуто в `<details>`), кемпинг
  с ценами и услугами, аренда — это контент главной из CMS. Цены стоят в таблице на `--bg-raised`,
  как на карточке события артборда, а не на железных плашках: на железе приглушенный текст светлой
  темы не проходит контраст. Железных плашек две — «как доехать» и трансфер, аренда и кемпинг
  стоят своими разделами.
- **Плитка таверн** — восьмая среди площадок, как на артборде, но ведет на раздел таверн, а подпись
  берется из названий таверн в CMS.
- **Подпись вордмарка** — название поселения из CMS, а не «поселение викингов IX века» артборда: подзаголовок
  сайта в CMS — длинная фраза для первого экрана, в колонку 168 px она не ложится.
- **Абзац под лентой дат** — текст раздела ближайших событий из CMS («поселение открыто только в дни
  событий»); на артборде под лентой ничего нет.
- **Подвал** — на артборде одна строка контактов (адрес, телефон, почта). В коде колонки «Контакты»,
  «Разделы» и «Соцсети», под ними юрлицо и возрастная пометка: это данные глобала «Сайт», а в одну строку
  артборда они не помещаются.

## Расписание

`src/app/(site)/raspisanie/page.tsx` читает контакты и все даты одним заходом `getSchedulePage()`
(`src/cms/schedule.ts`, склеен `cache` на запрос) и собирает страницу в общей рамке `SiteFrame`: заголовок,
фильтры, даты по месяцам, таблица цен, подвал. Строки — `scheduleRows()` (`_schedule/rows.ts`): даты,
которые еще не прошли (`upcoming`), по порядку дня и начала — порядок держит сама страница, а не сортировка
базы. Даты всех трех видов исходной `/tur` («27 сентября», «16.05.26», «01; 08; 15…») печатает один
форматтер `formatDate`: «10 октября, суббота», время — `formatTime`, «16:00 — 19:00, шоу 18:30».

**Фильтры — ссылки**, а не скрипт: месяц и событие живут в адресе (`?month=2026-10&event=ragnarek`),
страница собирается на сервере, у выбранного варианта `aria-current`. Варианты берутся из всех будущих
дат, поэтому сочетание месяца и события может оказаться пустым — тогда строка «по этому фильтру дат нет»
со ссылкой на все даты. Ссылки фильтров ведут на якорь `#dates`: после выбора страница открывается на
фильтрах, а не на шапке.

**Даты — только в `<time>`**, и не только дни: заголовок месяца («Октябрь 2026») и вариант месяца в фильтре
тоже в `<time dateTime="2026-10">`, потому что сдвигаются вместе с засевом. Проверка дат в `fonts.spec.ts`
ищет вне `<time>` и именительный падеж месяцев.

**Цена в строке** — от самого дешевого билета, как на главной (`cheapest` в `src/lib/events.ts`); все виды
билета — в таблице «Цены билетов» под списком. Кнопка «Купить билет» ведет в кассу этой даты (`ticketUrl`
события). Нет ни одной будущей даты — вместо фильтров, списка и таблицы стоит пустое состояние
с телефоном и почтой из глобала «Сайт» (D27: после конца сезона демо показывается так).

### Расхождения расписания с артбордом

Отдельной страницы расписания на артборде нет. Она собрана из языка плашки «Карточка события»: дата
Ponomar с `tabular-nums` и время Golos приглушенным цветом — как `card__date`, цена — `Price` с подписью
вида билета, таблица цен — как `.prices` развернутой карточки (`--bg-raised`, `--cut-sm`, строки через
`--line-soft`). Строки — списком с линиями, а не карточками: дат в сезоне десятки, и карточка с кадром
на каждую дату растянула бы страницу. Заголовки месяцев — Ponomar, как заголовки разделов главной.

## Как доехать

`src/app/(site)/kak-doehat/page.tsx` читает страницу `directions` и глобал «Сайт» одним заходом
`getDirectionsPage()` (`src/cms/directions.ts`) и собирает: заголовок и подзаголовок страницы из CMS, адрес
с картой, дальше все разделы страницы через `CmsSections` — парковка, маршрут на картах, рейсовые автобусы,
трансфер с точками сбора, оповещением, ценой, правилами и билетом. Якорь `transfer` — цель плашки трансфера
на главной (`/kak-doehat#transfer`).

**Карта грузится по клику** (`MapEmbed`, клиентский компонент): до клика на странице кнопка «Показать карту»
и ни одного запроса к Яндексу, по клику встает iframe виджета Яндекс Карт (`yandex.ru/map-widget/v1`, ключ API
не нужен) с меткой на точке из глобала. На исходном сайте Яндекс Карты подключены на 20 страницах сразу.
e2e подменяет ответ Яндекса заглушкой: тест проверяет, когда и что страница просит у чужого сервиса,
а не работу самого Яндекса; настоящая карта проверена руками (метка на поселении, 26 запросов к Яндексу
после клика, к `api-maps.yandex.ru` — ни одного). Точка на карте в контенте владельцев взята из их ссылки
на Google Карты в том же разделе — 54.8781221, 20.2789453.

Пары «город — точка сбора» на исходной странице стоят двумя отдельными списками; в контенте они сопоставлены
по строкам Тильды (у города и адреса одна координата `top`).

## Компоненты направления

`src/components/` — слой по артборду. Сверяются с ним глазами на витрине `/components`.

- `RunicText` — надписи своим руническим алфавитом. Строка приходит пропсом, путь считается на
  лету: CMS меняет заголовок, и он перерисовывается. Исходная строка остается в документе текстом
  (скрытый `span`), а не подписью к картинке; сами глифы лежат в `svg[data-runic]` с гранями
  `.runic__face` и `.runic__deep` — по этим классам замер контраста находит рунический текст, имена
  глобальные и менять их нельзя.
  Строка прячется именно `visibility: hidden`, и менять это на клип из артборда нельзя: замер
  контраста пропускает узел только по `visibility`, а клипованный текст попал бы в узлы, не дал бы
  ни одного закрашенного пикселя и уронил бы проверку «узлов без видимых глифов ноль».
  В алфавите 32 буквы, точка и тире — цифр нет: заголовок с годом отрисуется рунами без года,
  хотя скрытая строка год сохранит. Появятся цифры в заголовках — рисовать их знаками алфавита.
- `SvgDefs` — спрайт направления: орнаменты `ring-chain`/`ring-chain-v` и фильтры `wood-grain`/
  `iron-grain`. Рисуется один раз на страницу, остальные компоненты ссылаются на идентификаторы.
- `Ornament`, `Grain` — кольцевая цепь борре и процедурное зерно. Картинок нет: зерно считает
  `feTurbulence`, поэтому оно ничего не весит и не пикселится.
- `CutBox` — тесаные углы через `clip-path: var(--cut-*)`. Тень идет `drop-shadow`, а не
  `box-shadow`: второй рисуется по прямоугольнику и торчит из-под среза. Обводка — вторым слоем
  через `::before`, `border` на клипованной форме тоже срезается.
- `Button`, `EventCard`, `StonePanel`, `PhotoSlot`, `Price`, `Mark` (знак площадки из спрайта).
- `PhotoSlot` держит место под фотографию: кадр из медиатеки CMS (`next/image`) ложится поверх
  процедурной заглушки — градиент плюс зерно, — которая видна, пока кадр грузится. Подпись
  лежит на вуали `--veil-ink`: без нее она проваливается по контрасту (3,4:1 на заглушке), это
  проверяется тестом. Читается она не из-за заглушки: при alpha 0.94 кадр дает под текстом около
  6% цвета, поэтому разброс контраста между самым светлым и самым темным снимком меньше пункта.
- `Price` — знак рубля отдельным элементом текстовой гарнитурой (в Ponomar его нет). Между числом
  и знаком неразрывный пробел **и** `overflow-wrap: normal`: неразрывный пробел сам по себе не
  спасает, `overflow-wrap: anywhere` от окружения рвет строку и на нем. Разряды в числе тоже
  разделяются неразрывным пробелом — `formatAmount`: четырехзначные слитно, от 10 000 через пробел.
  `tone="plain"` красит цену цветом окружения — так она стоит в таблицах цен и на железной плашке.

### Расхождения с артбордом

Записаны, чтобы следующий блок и ручная сверка не приняли их за ошибку:

- **подпись на кадре** — на артборде это полноширинная плашка на градиенте, в коде вставная плашка
  со срезом на сплошной `--veil-ink`. Так контраст не зависит от того, что под кадром;
- **подпись под ценой** уходит блоком под число, а не стоит с ним по базовой линии: у длинной цены
  в узкой колонке строка иначе рвется.

## Шрифты направления

Ponomar (заголовки), Forum (капитель) и Golos Text (текст и знак рубля) подключены через
`next/font/local` в `src/styles/fonts.ts`, модуль импортируется в layout. Имя семейства задается
через `declarations: [{ prop: 'font-family', … }]` — иначе next/font назвал бы семейство по имени
константы, и `--font-*` разошлись бы с артбордом, а они сверяются с ним побайтово.
`adjustFontFallback: false`: свои запасные начертания next/font здесь не нужны, и у `next/font/local` флаг
действует — лишних `@font-face` в CSS нет (на сайте студии он не действует только у `next/font/google`).
Preload включен: направление одно, все три шрифта нужны на каждой странице, и next отдает их заголовком
`Link`. Константы в `fonts.ts` никто не импортирует, модуль подключается ради `@font-face`, но `export`
снимать нельзя: next/font требует `const` на уровне модуля, а неиспользуемая константа без `export` дает
три предупреждения `no-unused-vars`.

**Сабсеты.** `yarn subset:fonts` (`scripts/subset-fonts.mts`) качает исходники из `google/fonts`
по закрепленному коммиту (кеш в `node_modules/.cache`), режет их до `GLYPHS` из
`scripts/subset-glyphs.mts` и кладет в `src/styles/fonts/` рядом с OFL. Вывод детерминированный:
`tests/unit/font-files.test.ts` дважды запускает скрипт и сравнивает побайтово с тем, что лежит
в репозитории, то есть правка скрипта без пересборки файлов тоже роняет тест. Хинтинг выброшен, как
у самого Google Fonts для всех систем, кроме Windows; из OpenType-фич оставлены те, что браузер
включает сам, плюс `tnum` для `tabular-nums` — стилистические наборы Ponomar весили 16 КБ, а отрисовка
по умолчанию с урезанным набором совпадает попиксельно. Итого 61 КБ на три шрифта.

**Лицензии.** Рядом с каждым файлом лежит его OFL. У Forum лицензия резервирует имя «Forum», а сабсет по
OFL-FAQ 2.6–2.8 — модифицированная версия (набор знаков урезан, хинтинг снят), и носить это имя ему нельзя.
Поэтому скрипт переписывает в его таблице `name` семейство, полное имя, уникальный идентификатор
и PostScript-имя на «Kaup Caps» (`scripts/sfnt-name.mts`, harfbuzz в сборке `subset-font` этого не
умеет); копирайт и версия остаются. Имя семейства в CSS по-прежнему 'Forum' — оно сверяется с артбордом,
а запрет FAQ касается имени в меню шрифтов. Отсюда же `FILE_FAMILY` в e2e: Chrome сообщает имя из файла,
и для Forum это «Kaup Caps». Сторожит `tests/unit/font-license.test.ts`: зарезервированные имена берутся
из самих файлов OFL, и в таблице `name` сабсета их не должно быть нигде, кроме копирайта и лицензии.

**Покрытие знаков.** `tests/unit/font-subset.test.ts` собирает все знаки текстов репозитория через
AST TypeScript: строки, шаблоны и JSX-текст с раскрытыми сущностями (`&nbsp;` в AST — шесть латинских
букв, а не неразрывный пробел), плюс `content` в стилях. Знак вне `GLYPHS` роняет тест: он отрисовался
бы запасной гарнитурой. Тест сверяет тексты с `GLYPHS`, а не с файлами, и в самих шрифтах есть пробелы:
в Ponomar нет `№` и `₽`, в Forum — `Ѐ` и `₽`, в Golos Text — `Ѐ Ѝ ѐ ѝ` (их нет и в исходниках). Знак
рубля поэтому набирается Golos Text (`Price`), а `№` в заголовке Ponomar уйдет в запасную гарнитуру —
это поймает только e2e ниже, и только если такой текст стоит на проверяемой странице.

**Что рисуется на самом деле.** `tests/e2e/fonts.spec.ts` берет через CDP `getPlatformFontsForNode`
шрифты, которыми Chrome набрал глифы каждого видимого узла. Вычисленный `font-family` для этого
бесполезен: он одинаков и при незагруженном шрифте, и при знаке, выпавшем из сабсета. CDP отдает
шрифты узла вместе с вложенными строчными элементами, поэтому узлу разрешены первые семейства его
собственного текста и вложенного (у цены число — Ponomar, знак рубля — Golos Text).

**Запасные начертания.** Второе семейство каждого текстового `--font-*` — `'<Семейство> Metric
Fallback'`, объявленное в начале `tokens.scss` на `local()` шрифтах мака и Windows (Times New Roman,
Arial), Linux (Liberation, метрически совместимы с ними) и Android (Noto Serif, Roboto — не совместимы,
там подгонка ширины приблизительная, и ни один тест ее не проверяет: на CI срабатывает Liberation). У каждого
семейства начертание для всех знаков и отдельное для цифр (`unicode-range: U+30-39`) — цифры Times и Arial
расходятся с цифрами гарнитур сильнее букв, и с одним `size-adjust` суммы у Ponomar уходили на 6,6%.
Знаки, которые расходятся с гарнитурой так, что тянут за собой строку, получают свое начертание с точным
`size-adjust` по ширине самого знака (`GLYPH_FACES` в `tests/lib/fallback-texts.ts`): у Ponomar — пробел
(у Times уже на 20%) и крайние строчные «з», «т», «э», «е», «ю», «с», «р» (строчные Ponomar набраны
капителью, и «от» перед ценой уводило строку расписания на 19%; начертание для одной «т» ломало равновесие
дат), у Golos Text — длинное тире (у Arial шире на 44%, стоит в каждом диапазоне времени). Пока грузится
шрифт, эти буквы Times выглядят крупнее или мельче соседних («окТября»), зато ширина строки та же. Знаку
рубля начертание не поможет: в Arial и Liberation Sans его нет, рисует его системная замена — STIX Two Math
на маке, FreeSans на Linux (`SYSTEM_GLYPHS`), — и подгонка с DOM-сверкой его не учитывают. Вертикальные
override каждого дополнительного начертания пересчитаны на его `size-adjust`, так что высота строки у всех
одна (это сторожит юнит `tests/unit/fonts.test.ts`).

Метрики считает `yarn fallback:metrics` (только на маке, нужен артборд; скрипт идет через tsx ради
импортов из `src/`). Пара `size-adjust` подбирается так, чтобы худшее отклонение ширины было наименьшим
на всех эталонных текстах сразу (`tests/lib/fallback-texts.ts`): текст артборда по гарнитурам, все даты
словами форматтера, текст из одних цифр — суммы засева у Ponomar и Golos Text, числа месяца у Forum —
и видимый текст главной и расписания с настоящим контентом из `--page` (`yarn dev` на рабочей базе:
`--page http://localhost:3000/ --page http://localhost:3000/raspisanie`). Строки расписания со страниц
из `--page` меряются еще и в DOM со стилем своего узла (`collectRowTexts`, `measureStyledTexts`) и входят
в подгонку суммой по гарнитуре, а даты строк — всеми днями года (`YEAR_DATES`) в стиле узла даты. Разрядка
(`letter-spacing`) в модели — отдельное слагаемое: браузер добавляет ее поверх ширины знака, и `size-adjust`
ее не масштабирует (без этого Forum с разрядкой капители уходил на 1,9%). Страницы засева в подгонку
не передавать: по ним тест проверяет метрики, и проверка должна оставаться независимой.
Подгонка по одной кириллице артборда, как было раньше, оставляла Ponomar на заглавных заголовках страниц
на +2%, а без текста из одних цифр начертание цифр Forum уходило на 7%, уравновешивая буквенные тексты.
Числа месяца и суммы вместе одному `size-adjust` цифр не даются: у Golos Text цифры пропорциональные,
у Arial — одной ширины. С числами next/font (Forum 100,6%
против 85,8% по кириллице) абзац на 390 до загрузки шрифта переносился лишней строкой, и на Linux сдвиг
доходил до 0,017 — хуже, чем совсем без запасных начертаний. Поменялись шрифты, тексты артборда или
страниц — перезапустить скрипт, перенести вывод в `tokens.scss` и закоммитить
`tests/fixtures/artboard-text.json`: по этому снимку тест сверяет текст артборда на CI, а юнит на маке
проверяет, что снимок снят с нынешнего артборда.

Проверок три, и сторожат подгонку вторая и третья:

1. «Пока грузятся шрифты направления» — ответы `.woff2` задерживаются, страница рисуется запасными
   начертаниями, и сумма сдвигов макета до прихода шрифтов не выше 0,02. Это порог критерия, и он ловит
   только грубую ошибку: `size-adjust: 60%` дает 0,03–0,11, а числа next/font и полное отсутствие запасных
   начертаний проходят (на Linux 0,017 и 0,004).
2. «Метрические запасные начертания» — текст, набранный запасным начертанием, той же ширины и той же
   высоты над и под базовой линией, что настоящим шрифтом, ±2%: сторожит и `size-adjust`,
   и `ascent`/`descent`-override. Тексты — видимый текст `/`, `/components` и `/raspisanie` по гарнитурам и эталонные
   тексты (Forum сумм не набирает, у него вместо сумм числа месяца). Из текста страниц выброшены длинное
   слово засева и даты (`<time>`): засев ставит даты от сегодняшнего дня, и с ними тест на той же сборке
   краснел или зеленел по дням; даты целиком проверяет эталонный набор. **Даты — только внутри `<time>`**:
   дата вне него снова делает сверку зависимой от дня, это сторожит отдельный тест на `/` и `/raspisanie` (слов месяцев
   и дней недели вне `<time>` нет; слова проверяются по каждому узлу — в склейке узлов слово месяца
   сливается с соседним, и дата `EventCard` на `/components` проходила незамеченной). `EventCard`
   печатает дату вне `<time>` — на `/components` даты постоянные, но на странице из CMS ее надо
   обернуть. Меряется на кегле 1000px: на Linux Chrome
   округляет ширину глифов до пикселя, и на 100px это давало до 1% расхождения с маком (на 1000px
   Ponomar и Forum совпадают до 0,0005, Golos Text — до 0,004); на 100px в Linux эталонная сверка
   с метриками B65 была бы красной (суммы Ponomar 1,0221 против 1,0081 на 1000px). Тест проверяет
   метрики шрифтов, а не то, что рисует раннер: на реальных кеглях Linux headless округляет так же,
   на суммах Ponomar и тексте Golos это 2–3%, и сторожит это только тест сдвига. Canvas не учитывает
   `font-variant-numeric`: время в панели и карточке набрано Golos с `tabular-nums`, а тест меряет
   пропорциональные цифры — строки расписания проверяет третья проверка. Цифры Forum привязаны к числам
   месяца (0,995), а на наборе 0–9 и на суммах запасное начертание уже на 7 и 14%: Forum сумм не набирает.
   Подогнанные метрики укладывают эталонные тексты в 1,5%, страницы засева — в 1,9% на маке (Golos Text на
   `/raspisanie` 0,9811) и в 1,6% на Linux. Регрессию «числа next/font у Golos Text» (`size-adjust` 108,8% без
   пересчета override) ловят все сверки с Golos: по ширине — `/components` 1,0234 и артборд 1,0220 (`/` — 1,0195,
   в допуске), по высоте — все, ascent 1,0398. Если 108,8% получит только начертание букв, картина та же: по
   ширине `/components` 1,0228 и артборд 1,0204, по высоте все. Без начертания цифр у Ponomar падают эталонная
   сверка на суммах (1,0621) и `/raspisanie` (1,0242). Вертикальные метрики начертания цифр этот тест не видит:
   canvas берет `fontBoundingBox*` у первого начертания, покрывающего пробел, и непересчитанный `ascent-override`
   цифр дает на суммах 1,0000 — высоту начертания цифр сторожит только юнит `tests/unit/fonts.test.ts`. Тест
   падает и тогда, когда начертание не объявлено или не нашло ни одного локального шрифта.
3. «Строки расписания… суммой по гарнитуре в DOM со стилем узла» — canvas не знает `font-variant-numeric`,
   а время в строках набрано цифрами одной ширины. Каждый текстовый узел строк `/raspisanie` копируется
   со всеми свойствами текста своего элемента (`ROW_TEXT_STYLE`: `font-variant-numeric`, `text-transform`,
   разрядка), увеличивается до 1000px и меряется настоящим шрифтом и запасным; ширина складывается
   по гарнитуре, высота над и под базовой линией сверяется по каждому узлу, ±2%. Суммой, а не по узлу:
   у строчных Ponomar отношение знака к Times от 0,63 до 1,36, и две даты одного формата давали 0,948
   и 1,058 — никакие метрики не уложат каждый короткий узел в 2%. Даты строк засева сдвигаются каждый
   день, поэтому они в сумму не входят, а меряются всеми днями года (`YEAR_DATES`) в стиле узла даты;
   знак рубля (`SYSTEM_GLYPHS`) выброшен из суммы — его рисует системный шрифт. Мак: Ponomar 0,9993
   строки и 0,9938 даты года, Forum 1,0025, Golos Text 0,9864; Linux: 0,9992, 0,9936, 1,0025, 0,9868.
   На метриках до строк расписания Ponomar давал 0,9788.

Lighthouse запасных начертаний не видит вовсе: на localhost шрифты уходят в preload и приезжают раньше
первой отрисовки, так что даже с `size-adjust: 60%` его CLS оставался 0. Порог CLS в `lighthouserc.cjs`
сторожит все остальное.

## Проверки контраста

Их две, и вторая не заменяется первой:

1. **По токенам** (`tests/unit/token-contrast.test.ts`) — пары «текст на фоне» из таблицы
   артборда не ниже 4,5:1 в обеих темах. Дешевая страховка accessibility 100.
2. **На отрисованной странице** (`tests/e2e/rendered-contrast.spec.ts`) — каждый текстовый узел
   главной, расписания и «как доехать» не ниже 4,5:1 в обеих темах на 1440 и 390 (новая страница — строка
   в `MIN_PAGE_TEXT_NODES` с числом узлов, закрепленным по факту). Токенная проверка по устройству не видит текст
   поверх фотографий, градиентов и процедурных текстур, а оба провала артборда сидели именно там.

Три правила замера, оплаченные ошибками артборда, менять нельзя:

- контраст считается к фону под **каждым** пикселем строки, а не только под ядром глифа:
  текст в цвет фона кадры нигде не разведут, маска окажется пустой и проверка промолчит;
- допуск на сглаживание задан **на строку** (2 пикселя), а не долей узла: доля от узла на
  длинном тексте прячет под допуском целое слово;
- рунические надписи (`svg[data-runic]` с гранью `.runic__face`) меряются **отдельным кадром**:
  гасить их вместе с остальным текстом нельзя, фаска буквы подменяет собой фон под ней.

- полупрозрачный текст меряется **с учетом своей альфы и `opacity` всех предков**: цвет текста сначала
  смешивается с фоном под пикселем, потом считается контраст. Раньше замер брал первые три числа
  `getComputedStyle().color` и видел в таком тексте непрозрачный — врал в зеленую сторону. Сам замер
  сторожит `tests/e2e/contrast-measure.spec.ts` на странице с заранее известным ответом.

Неотрисованный текст (в свернутом `<details>`, под `display: none`) замер пропускает по
`checkVisibility()`, а тест раскрывает меню таверн, чтобы их текст тоже померить. Раскрытое меню шапки
на 390 меряется отдельным тестом с `scope`: оно лежит поверх страницы и закрыло бы собой чужие узлы.

Тест падает и тогда, когда текстовых узлов на странице меньше восьми (пустая страница не должна
проходить проверку молча) и когда у узла кадры нигде не разошлись: значит, глифов на странице
не видно совсем — текст под непрозрачной плашкой прошел бы порог молча. Такие узлы тест называет
поименно. Отдельный текстовый узел из одних знаков вроде « · » закрашивает меньше десяти пикселей и тоже
попадет в «слепые» — разделители ставятся внутрь соседнего элемента.

`tests/e2e/shell.spec.ts` сторожит оболочку: страница отдает `lang="ru"`, без куки и с неизвестным
значением куки — темную тему, а размеры переключаются **ровно** на брейкпоинте: на 640 действует
узкая колонка, на 641 — широкая. Пары ширин артборда (390 и 1440) для этого мало — она оставляет
верным любое число между ними. Само число закреплено дважды: юнит-тест сверяет медиазапрос
с `NARROW_BREAKPOINT` в `tests/lib/consts.ts`, e2e проверяет его действие по обе стороны границы.

## e2e-база и засев

Страницы читают CMS, а контент владельцев на CI не засевается, поэтому e2e-сервер работает со своей
базой `kaup39_e2e` и своей медиатекой `media-e2e/` (`playwright.config.ts`: `yarn seed:e2e && yarn build &&
yarn start`). Засев (`tests/e2e/seed/`) выдуман под тесты: прошедшие даты рядом с будущими (сдвиги
от сегодняшнего дня по Калининграду), длинное слово без пробелов в каждом виде текста из CMS, кадры первого
экрана худшие для контраста своей темы (почти белый вечерний, почти черный дневной). Засев сам создает
базу, стирает ее схему и каталог медиа и откажется работать с базой без суффикса `_e2e` или с каталогом,
который совпадает с `media/` или лежит выше него: пути сравниваются разрешенными (`tests/e2e/seed/guard.ts`).

Тесты, которые меняют базу, лежат в `*.state.spec.ts` и идут отдельным проектом `state` после всех
остальных и по одному (`workers: 1`): тест пустого расписания снимает даты через REST под администратором
засева и возвращает их в `afterAll`, тест первого экрана так же подменяет название, адрес, заголовок
и подзаголовок текстами обычной длины. Ссылку на расписание в первом экране он проверяет не на засеве:
с длинным словом сразу в пяти текстах первый экран не обязан вмещать кнопку, а тест переносов без этого
слова не проверял бы ничего. Сервер, поднятый руками на 3200, Playwright переиспользует: перед прогоном гаси его,
иначе тесты пойдут по чужой базе, а засев оборвется на середине.

Сверка запасных начертаний (`fonts.spec.ts`) узлы с длинным словом засева и даты не учитывает: одно слово
заглавными из восьмидесяти букв занимало треть текста Ponomar и уводило ширину на 2,6%, а даты засева
меняются каждый день.

## Lighthouse

`lighthouserc.cjs`: три прогона, `aggregationMethod: 'pessimistic'` — порог считается по худшему
прогону, а не по лучшему. Правило то же, что у сайта студии, и юнит-тест сверяет
значение с `../site/lighthouserc.cjs`, когда тот доступен. Пороги: performance и SEO не ниже 90,
accessibility ровно 100, CLS каждого прогона не выше 0,02. Первый прогон на свежем раннере —
прогревочный и в assert не входит. Меряются главная, расписание и «как доехать», каждая по три прогона. На CI они
меряются на засеве (свой Postgres в джобе, `yarn seed:e2e`),
локально — на той базе, что в `.env`, то есть на настоящем контенте с фотографиями владельцев. Best
practices пока 96: у сайта нет `favicon.ico`, и 404 на него уходит в консоль.

Репозиторий публичный ради раннеров: у публичных они на 4 CPU, у приватных на 2, и на двух главная
получала 0,86–0,89. Раннеры приходят разных классов CPU; шаг «CPU class and score of each run» пишет в лог
`benchmarkIndex`, оценку и TBT каждого прогона. Зеленый засчитывается, только если среди прогонов есть
медленный класс — `benchmarkIndex` ниже 2600: на быстром главная проходит всегда. Если все три прогона
попали на быстрый класс, джоб перезапускается (`gh run rerun <run> --job <job>`), пока не попадется медленный.

## Конвенции кода

- Компоненты — стрелочные функции; тип пропсов `ComponentNameProps` через `type`, не `interface`.
- Константы и типы — в `consts.ts` и `types.ts` рядом с кодом, который их использует.
- SCSS без комментариев; цвета, шрифты, срезы и тени — только через `var(--…)`.
- Медиазапросы только `max-width`. `hyphens: none`, `hyphens: auto` не использовать.
- Текст, приехавший из CMS, не вылезает из контейнера: `overflow-wrap: anywhere; min-width: 0`.
  Исключение — цена со знаком рубля: там разрыв запрещен, иначе знак уезжает на свою строку.
- Буква «е» вместо «ё». После коротких предлогов — неразрывный пробел.
- Новый критерий из `../ROADMAP.md` сначала становится тестом, потом кодом.
