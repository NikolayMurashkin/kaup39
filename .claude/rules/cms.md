# CMS

Payload 3 в том же приложении: админка `/admin`, REST `/api/*`, GraphQL выключен. Интерфейс админки по-русски.

База, переменные окружения, миграции — ядро `CLAUDE.md` («База и окружение», «Стенд и деплой»).

**Коллекции** (`src/cms/collections/`):

- `events` — название, slug, описание, «входит»/«за доплату», галерея, цены по видам билета, ссылка на кассу, даты через join;
- `schedule` — событие, день, начало, конец, огненное шоу;
- `pages` — главная, «как доехать», кемпинг, корпоративы: заголовок, подзаголовок, кадры первого экрана, карточка на главной `teaser`, разделы из блоков `text`/`list`/`prices`/`links`/`photos` с якорями;
- `zones` — со знаком площадки из спрайта направления;
- `taverns` — с меню по разделам; `media`, `users`.

Контакты, соцсети, точка поселения на карте, инструкция по возврату билетов — глобал `site`: нужны на каждой странице. Точка на карте необязательна: колонки NOT NULL в базе с уже заполненным глобалом Payload без вопроса не добавит (`yarn import:content` зависал на подтверждении); без точки страница просто не показывает кнопку карты.

**Касса одна — Radario.** Ссылка на билет — единственное поле-ссылка у события, обязательное, валидатор `validateTicketUrl`: адрес разбирается целиком → не проходят `edinoepole.ru`, `https://https://radario.ru/…` и `radario.ru.example.com`. Из админки такая ссылка не сохраняется (проверено руками и `tests/integration/cms.test.ts`); `tests/unit/ticket-links.test.ts` сторожит, что валидатор висит на поле и второго поля-ссылки у события нет.
Кнопку «Купить билет» можно поставить и в раздел страницы → все остальные поля-ссылки (`links`, пункты `list`, соцсети в `site`) идут через `validateLinkUrl`: полный адрес с https; имя второй кассы не встречается ни в адресе, ни в разобранном хосте (так не проходят точка в конце хоста, `%2E` и двойная схема). Тест обходит все коллекции и глобалы из `src/cms/schema.ts` — того же списка, что берет конфиг → новое поле-ссылка без валидатора в любой из них его роняет.

**Даты.** День хранится полднем UTC — так сохраняет календарь админки (`pickerAppearance: 'dayOnly'`), так же пишет импорт. Страницы получают день строкой `YYYY-MM-DD` по Калининграду из `getSchedule` (`src/cms/schedule.ts`), время — строками `ЧЧ:ММ`; конец позже начала проверяет валидатор («с 12:00 до 12:00» с исходной `/tur` не пройдет).
Кеша у `getSchedule` нет: страницы и так рендерятся на каждый запрос (layout читает куку темы), правка в админке видна со следующей загрузки — сторожит интеграционный тест. Добавишь кеш → добавь и сброс по `afterChange`.

Факты (`src/cms/facts.ts`) и импорт текстов — тема `content-import.md`.
